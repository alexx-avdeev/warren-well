## Project-specific notes

- Target chip: `esp32c6`; keep dependencies, HAL features, and examples compatible with this chip.
- Check the `generator parameters:` comments in `src/bin/main.rs` before changing code that depends on selected generation options.
- This is a `#![no_std]` / `#![no_main]` project. Avoid `std`; use `core` and embedded-friendly crates.
- `alloc` is enabled. The heap is initialized in `src/bin/main.rs` with `esp_alloc::heap_allocator!`; adjust the heap size there if allocations fail.
- `.cargo/config.toml` contains the generated target, runner, build flags, and `[env]` defaults. Espressif crates expose additional configuration through environment variables; use `esp-config` to inspect/set those options. The linked "Additional configuration" sections for the enabled Espressif crates document crate-specific variables; keep project-specific defaults in `[env]` instead of hard-coding them in source.
- Logging uses `log`/`esp-println`; the default filter is `ESP_LOG=info` in `.cargo/config.toml` and can be overridden from the environment.
- `cargo run` uses `espflash` as configured in `.cargo/config.toml`. This path flashes through the board's serial/USB bootloader connection.
- If flashing fails, check bootloader mode, serial-port permissions, the selected port when multiple boards are connected, and that the `--chip` in `.cargo/config.toml` matches the target.

## Water meter project notes

- Hardware: ESP32-C6 (QFN40 rev v0.1), 16 MB flash, native USB-Serial-JTAG on `/dev/ttyACM0`. Base MAC `f0:f5:bd:0b:ec:e4`.
- Architecture proposal and phased plan: `docs/ARCHITECTURE.md`. Read it before adding modules; keep the module layout in §3.
- Toolchain: rustup stable (`~/.cargo/env`), target `riscv32imac-unknown-none-elf`, `espflash` 4.6, `esp-generate` 1.4. Nothing ESP-IDF/C is installed; stay pure Rust.
- Serial access requires the `dialout` group (already added; needs re-login) — until then prefix flash/monitor with `sudo -E env PATH="$PATH"`.
- `espflash --monitor` needs an interactive TTY. From a non-interactive shell read logs with `stty -F /dev/ttyACM0 115200 raw -echo; timeout 5 cat /dev/ttyACM0`.
- Sensor: DFRobot A02YYUW ultrasonic level sensor on UART1 (9600 8N1, 4-byte frame `FF H L SUM`, mm). Data goes to a Ruby on Rails farm-management app (not in this repo) via plain HTTP JSON POST on the LAN (TLS optional later); solar/12 V powered, see §1, §4 and §7 of the architecture doc.
- Layout: `crates/tank-core` = hardware-free logic with host tests; root crate = firmware. Run core tests with `cargo test -p tank-core --target x86_64-unknown-linux-gnu --config 'unstable.build-std=["std","panic_abort"]'`.
- `README.md` holds the status table, BLE service and HTTP API; keep it in sync when adding characteristics or routes.
- Dev conveniences: `WIFI_SSID`/`WIFI_PASSWORD`/`API_URL` build env seed an empty flash; `tools/` has BLE test scripts and a hostapd/dnsmasq test-hotspot config. WiFi power save is deliberately off (see README quirks) — do not re-enable without testing reachability.
